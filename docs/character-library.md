# Заготовка хранилища персонажей

Статус: контракт и тестовый адаптер в памяти. Постоянное общее хранилище и его интерфейс ещё не реализованы. Текущая библиотека редактора по-прежнему находится в `project.characters` и сохраняется вместе с квестом.

`character-library.js` предоставляет `createMemoryRepository(initial)` и асинхронные методы:

- `list()` — копии всех записей;
- `get(id)` — копия записи либо `null`;
- `put({id, name, image})` — создать или обновить запись, вернуть копию;
- `remove(id)` — удалить запись, вернуть признак удаления.

`image` — встроенный PNG/JPEG/WebP; PNG и WebP сохраняют прозрачность. Проверка данных общая с редактором и HTML-экспортом. Адаптер в памяти не переживает перезапуск и пока не подключён к странице.

## Следующий этап

1. Реализовать тот же контракт поверх отдельной базы IndexedDB `macroquest-character-library`, не меняя хранилище текущего проекта.
2. Добавить окно общей библиотеки: список, поиск, создание, редактирование, удаление.
3. При добавлении в квест копировать персонажа в `project.characters`; при конфликте идентификаторов выдавать новый ID. Размещение остаётся в `scene.actors`.
4. Изменения или удаление в общей библиотеке не должны менять уже созданные квесты. Обновление копии — отдельное явное действие.
5. Добавить импорт/экспорт библиотеки с версией формата, ограничения размера и обработку ошибок/квоты IndexedDB.

Пример PNG для будущей библиотеки: `assets/characters/test-wanderer.png`. Проекты и прохождения из браузера автоматически в Git не попадают; их нужно экспортировать отдельно через интерфейс.
